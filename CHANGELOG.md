# Changelog

All notable changes to this project are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); this project uses
[semantic versioning](https://semver.org/) for the app version in `pubspec.yaml`.

## [Unreleased]

### Added

- **Factions.** Guilds, cults, houses and gangs are now first-class world nodes with a kind, a goal,
  an emblem and DM notes. They live in the same graph as locations and NPCs, so "who is allied with
  whom" and "who belongs to what" are one picture — membership is just a typed bond
  (`WorldLinks`), not a second mechanism. Reachable from **NPCs → Factions**, from the world graph,
  and from the command palette.
- **Progress clocks.** Segmented clocks for sieges, rituals and spreading rumours. Tap a segment to
  set it, or use the `+` button. A clock can stand alone on the Session tab or hang off a quest or
  a faction. Filling one does *not* close it — you close it once you have played the consequence,
  which is written on the clock itself.
- **Android build.** `android/` now exists and `flutter build apk --release --split-per-abi`
  produces a working APK (~42 MB for `arm64-v8a`). Launcher icons — legacy and adaptive — are
  generated by `tools/build_icon.dart`, not by an extra package. Link-based music downloading needs
  an external `yt-dlp` binary and therefore hides itself on Android instead of pretending to be
  installable.
- **Open-format export.** Codex tree → Markdown (page hierarchy becomes heading levels), campaign →
  JSON (characters, world, factions, bonds, quests, clocks, session log). These are *not*
  restorable and carry no media; they exist so months of notes are never locked inside this app.
  Both live next to the backup buttons.
- **Record routes.** `/npcs/<id>`, `/world/<id>`, `/quests/<id>`, `/characters/<id>`,
  `/combat/<id>`, `/shops/<id>`, `/codex/<id>` and `/npcs/faction/<id>` open the record itself.
- **Encounters link to a location again.** The link used to live inside the battle-map table and
  died with it; it is now a plain column, set from the encounter briefing panel and read back as an
  "encounters here" strip on the location page.
- **A test that keeps the two translations in step.** `app_en.arb` and `app_tr.arb` must have the
  same keys and the same placeholders. `gen-l10n` silently falls back to the template language for
  a missing key, so an English screen could show a Turkish sentence and nothing would fail.

### Changed

- **The command palette opens the record, not the tab.** Searching "Gundren" used to drop you on
  the NPC list; it now opens Gundren. Library hits (monster, spell, item) no longer navigate at all
  — the stat block opens in place, so you can check a goblin's AC without leaving the combat screen.
- **Big UI files were split** into `part` files: the character sheet (3 154 → 1 349 lines), the
  Codex document page (2 040 → 646) and the Codex block editors (2 419 → 638). Same libraries, same
  private scope, no import churn.
- **Macros no longer have a "who can see this" scope** and their rolls now land in the roll log.

### Removed

- **The LAN server and the player web panel are gone.** DM Table is now a single-seat tool: there
  is no HTTP/WebSocket server, no QR code, no per-player snapshot, no chat, no presence panel and
  no browser client. `lib/net/`, `lib/player/`, `lib/main_player.dart`, `web/`,
  `assets/player_web/` (26 MB) and `tools/build_player_web.dart` were deleted, along with the
  `shelf*`, `web_socket_channel`, `qr_flutter`, `network_info_plus` and `web` dependencies. The app
  no longer opens a socket at all.
- **The battle map is gone.** Grid, tokens, walls, doors, fog of war, lighting, sound sources,
  drawing and tile layers, AoE templates, the dungeon generator and the Foundry/VTT importer were
  removed with it — roughly 16 700 lines plus ten database tables. Locations keep their region map
  with pins; the encounter screen keeps initiative, damage, conditions and the loot panel.
- **Player-facing state was dropped from the schema (v48).** `character_notes` and the ten
  `battle_*` tables are dropped; so are `locations.revealed`, `locations.map_preview_path`,
  `map_pins.revealed`, `shops.open_to_players` / `map_accessible` / `requires_approval`,
  `quests.shared` / `acceptances_json` / `share_mode` / `vote_status` / `reward_pool_json`,
  `combatants.initiative_rolled` / `hidden_from_players` and `macros.scope`. **This migration is
  one-way** — back up before first launch if those rows still matter.

### Changed

- **Session tab.** "Open the table" is replaced by what the seat actually needs: session log, roll
  log, ongoing journey, plus macros/downtime/recap/backup in the app bar.
- **Roll log.** Rolls used to be collected by the LAN server. They now live in an in-memory
  provider on the DM side and collect every roll made in the app — ability and skill checks from
  the sheet, the dice sheet, macros and Codex dice blocks.
- **Short rest.** The DM spends Hit Dice per character from the party rest panel instead of opening
  a rest for players to spend their own.
- **Loot sets.** "Show to players" became "Give": the set is poured into a shared party bag.
- **Quests.** Sharing, individual accept/reject, party voting and reward pools were replaced by a
  single "who took this job" list of characters. Concrete rewards (coins + items) stay.
- **Shops.** "Open to players", "reachable from the map" and "requires approval" are gone; the
  open/closed world state and the purchase flow (which now deducts gold and stock for a chosen
  character) remain.

> that the removal above supersedes.

### Fixed

- **Upgrading an existing campaign file failed at "installing content".** The v41 migration step
  read `battle_tokens` through a *generated* query, and a generated query always asks for the
  table's current column list — including columns the very next step was about to add. Every
  existing file therefore died on `no such column: battle_tokens.rotation_deg`. Migrations now read
  through raw SQL that names only the columns present at that point.
  Two follow-on problems came out of the same incident and are fixed too: drift does not wrap
  `onUpgrade` in a transaction, so the half-applied `ALTER TABLE`s survived while `user_version`
  did not advance, and the next launch failed with `duplicate column` instead — the new columns are
  now added only if missing, so a file stuck between the two errors heals itself on the next open.
  Regression cover was missing because the only migration fixture started at v23, which skips every
  `from >= 39` block; there is now a v39/v40 fixture that exercises them.

- **Fog of war left permanent dead spots.** Grid cells were indexed straight from the alignment
  offset, so a map whose grid did not start at pixel zero produced negative column/row numbers.
  The fog bitmap silently dropped those, and the strip along the top and left of such a map could
  never be revealed while the overhanging strip on the right could never be written. Cell indices
  are now zero-based and always span the whole image. Revealing also samples the four inner corners
  of a cell when its centre falls outside the vision polygon, so doorways, corners and narrow
  corridors stop staying black while the room around them opens.
- **The battle map reset its zoom and pan on its own.** Every data refresh (a token moved, fog
  grew, the grid changed) briefly replaced the canvas with a loading spinner, which destroyed the
  transformation controller inside it. The controller now lives on the page and the last loaded
  scene stays on screen while a refresh is in flight.
- **Scroll-wheel zoom did not work while drawing.** `InteractiveViewer`'s scale handling has to be
  off for the drawing tools (it wins the gesture arena and swallows drags), which also killed the
  wheel. Wheel zoom and middle-mouse panning are now handled directly and work in every tool,
  including the new calibration mode.
- **Dragging a token was unreliable.** The token's own drag recogniser competed with
  `InteractiveViewer`'s scale recogniser in the gesture arena, so whether a drag moved the token or
  the map depended on which one claimed the pointer first. All map interaction — click, drag, token
  move, marquee — now runs off raw pointer events outside the arena, so the outcome is
  deterministic.
- Editing a character now propagates to everything derived from the edit. Changing species used to
  write the species key and nothing else: speed stayed at a hardcoded 30 ft for everyone, and
  proficiencies kept describing the old origin. Speed is now read from the species, and derived
  proficiencies are recomputed.
- Derived proficiencies touch the character row *after* they are written. The sheet re-reads
  proficiencies by watching that row, so changing background or species used to leave the previous
  list on screen until the page was reopened.

### Changed

- **Fog computation moved out of the repository into a pure function** (`computeFogReveal`), which
  made it both testable and movable: scenes with 120+ walls now run it on a background isolate so
  dragging a token does not stutter. Smaller scenes stay inline — spawning an isolate would cost
  more than the work.


- **Holding `Shift` suspends grid snapping** while dragging tokens or drawing walls, matching
  Foundry — previously the only way was to toggle the setting off and back on.
- **Wall ends snap to nearby wall ends** before falling back to grid corners. Two lines that look
  joined but are a pixel apart leak light and movement through an invisible crack, and finding that
  crack afterwards is miserable.

- **The DM's map is no longer darkened by the lighting rule.** Adding a single torch used to plunge
  the whole scene into darkness for the person *preparing* it. Light now only restricts what is
  visible in the player view (and in what the fog remembers); in the DM view it reads as a warm
  halo and nothing more. DM fog also lightened considerably — it is a note that says "the party has
  not been here", not a curtain over the map.

- **The DM is no longer blocked by walls.** Dragging a token as DM puts it wherever you point —
  inside a wall, on a roof, off the map. Placing a creature is the DM's job; rule enforcement stays
  on the player side and in the server, which still validates every move a player makes.
- **A battle map stays a battle map.** Marking a place as one is a property of the place, not a
  mode you toggle: it opens straight into the tactical view from then on, and Back still goes up to
  the parent place. There is a switch in the map panel to turn it back into a region map.
- **Left-drag on empty ground is now marquee select** rather than pan (matching Foundry); the map
  is panned with the middle or right mouse button, or with two fingers on touch.

- **The battle map now uses a Foundry-style layout.** The canvas is full-bleed and the interface
  floats on top of it: a vertical tool rail on the left with a contextual options strip beside it,
  a slim scene bar on top, zoom controls bottom-left, and a collapsible settings panel on the
  right. The old arrangement (a chip toolbar above the map plus a permanent 320px column) squeezed
  the map — the thing you actually look at — into a small window.
- **Tokens created from characters carry their own look.** Size comes from the species (Small and
  Medium fill one square, Large fills 2x2), speed comes from the species too, and the portrait
  becomes the token art. With no portrait the token shows initials; with no known size it is one
  5 ft square.
- **Marker-only places no longer clutter the world node graph.** Pins of the "place with no map"
  kind keep a real location record behind them so quests and the travel planner can see them, but
  they are not places you go to and they are no longer drawn as nodes.
- Fog edges are feathered and every fifth grid line is drawn slightly stronger.
- **Walls no longer stop the DM.** Running the table means putting a creature inside a wall, on a
  roof or off the map when the fiction calls for it. Wall collision is now enforced only on the
  player side (and still re-validated on the server), never against the DM.
- **The turn order sits on top of the map.** When a battle map is linked to an encounter, the scene
  bar shows the combatants as portraits with the active one enlarged and ringed, a round counter,
  and a start/next-turn button. Tapping a portrait selects that token and centres the view on it —
  no more switching to the combat screen to answer "whose turn is it?".
- **Multi-select and group move.** Dragging on empty ground draws a selection frame (Shift or Ctrl
  adds to the selection, as in Foundry); dragging any selected token moves the whole group and
  keeps its formation. The side panel switches to bulk actions — show/hide from players, fog on/off,
  delete — while more than one token is selected. Arrow keys and WASD move the whole selection.
- **A battle map is what a place *is*, not a mode you toggle.** Places marked as battle maps open
  straight into the tactical view, and back still goes to the parent place. Turning a place into a
  battle map (or uploading a map image for one) sets the flag; a switch in the map panel turns it
  back. Existing places that already have walls or tokens are flagged automatically on upgrade.
- Left-drag on empty ground now selects instead of panning; the map is panned with the middle or
  right mouse button, or two fingers on touch.


- Renamed the project from *DM Masası* to **DM Table**: Dart package `dm_masasi` → `dm_table`,
  Windows binary `dm_table.exe`, Android application id `com.rpgproje.dm_table`, and the visible
  app name in both languages. Existing campaign database files keep their previous names, so no
  user data is affected.
- Applied `dart format` across the codebase and enforced it in CI.
- Turkish now reaches the screens where players actually read rules. The character sheet and the
  level-up flow render class and subclass feature text through the same translation overlay the
  compendium already used, so gaining a feature no longer drops the reader back into English.
  Feats on the sheet are rebuilt from the library record instead of the English text stored on the
  character, which is what made their translation fall through.
- Ability and skill names (`Strength`, `Stealth`, `STR`) are localised through `L10n` instead of
  the `Ability`/`Skill` enum labels; the enum labels stay English because the SRD parsers and
  `fromName` lookups match on them. Spell cards, the spell picker and the spell list now localise
  level, school, ritual, concentration and the field labels. Item rarity, item category, monster
  size and creature type dropdowns read from the glossary rather than showing raw database values.

### Added

- **Area damage in one pass.** A pinned template now has an *apply to everyone inside* action:
  tick whoever saved, and each token takes full or half (or none, for Evasion). Large creatures
  count if *any* of their squares is covered — a giant with one foot in the fire takes the hit.
  Concentration saves triggered by the damage are reported together rather than as a stack of
  toasts. Deducting eight creatures' hit points by hand was the slowest minute of any fight.
- **Global search (`Ctrl`/`Cmd`+`K`)**, also on the navigation rail. One box over monsters, spells,
  items, magic items, characters, places, NPCs, quests, codex pages, shops and music. The app spans
  seventeen branches now; knowing *which tab* a thing lives in had become the bottleneck.
- **Roll log on the DM's screen.** The shared log existed only in the player panel, so the DM could
  see neither their own last roll nor what a player rolled a minute ago.
- **Token HUD** — the selected token gets a small strip with damage, hide/show, target, see-through
  and settings, so the common four actions no longer need the context menu.
- **Scene switcher** in the top bar: one tap between battle maps (shown when no encounter is
  attached, where the initiative strip takes over).
- **Blindsight, tremorsense and truesight** alongside darkvision. Blindsight and truesight share
  darkvision's geometry (no light needed, walls block); tremorsense is modelled properly as
  *touch, not sight* — it passes through walls, and is checked before the line-of-sight test rather
  than after, which is what a naive implementation gets wrong.
- **Players can ping too.** The map ping was one-way, which made for an odd silence: the DM could
  say "look here" and a player could not answer "what about here?".
- **Bulk save requests** from the encounter screen: pick an ability and a DC, and every player
  character is asked at once.
- **Daily automatic backup**, taken quietly on launch and pruned to the last seven. Backups existed
  but only for whoever remembered to make one.


- **Drawing layer.** Freehand, rectangle, ellipse, arrow and text marks, in six colours, kept
  deliberately separate from area templates: a template is a rules object ("who is inside this
  cone"), a drawing is a note ("this is a pit", "the door opens here"). Until now there was no way
  to write on the map at all.
- **Tile layer.** Drop images onto the map (furniture, rugs, a roof) with size, rotation and
  opacity, and a switch for whether they sit above or below tokens — so a canopy can hide what is
  under it. Aspect ratio is preserved on resize.
- **Scene darkness and weather.** A day↔night slider plus rain, snow or fog overlays. The lighting
  rule is now tied to darkness: a torch in a daylit market square no longer darkens the scene,
  because the rule only engages once the scene is actually dark.
- **Condition badges on tokens.** Conditions used to render as a line of text under the token
  ("poisoned · stunned · prone") that was unreadable from across the table and wider than the token
  itself. They are now small coloured badges laid across the top of the token, and tapping one
  clears that condition without opening the combat screen.
- **Attack → target → damage in one flow.** `T` on the map marks a target, and the monster attack
  sheet now shows that target, whether the roll beats its AC, and an *Apply* button that writes the
  damage. If the target was concentrating, the DC 10 / half-damage save is surfaced immediately —
  the most-forgotten rule at the table.
- **Group initiative**: one roll for all monsters of the same kind (the DMG's own suggestion), so
  six goblins occupy one place in the order instead of six.

- **Light and sound sources are their own map objects**, not tokens. A torch hangs on a wall — it
  has no turn, no hit points and does not belong in the combat list, which is what made the old
  "object token with a light radius" approach wrong. Both are placed by clicking with the new tools
  and drawn as small fixed-size markers only the DM sees; players get the *effect*, not the source.
  Lights carry bright/dim radii, a colour, and a beam angle (drop below 360° and it becomes a
  directional cone, for lanterns and spotlights); presets cover candle, torch, lantern and *light*.
  Sounds carry a radius, an optional track and a volume, tell you how many tokens can hear them
  through the walls, and can be auditioned straight from their window.
- **See through a token's eyes.** Right-click a token → *Gözünden bak*: the map is redrawn using
  only that creature's vision, with hidden tokens hidden and fog at full player darkness. A badge
  in the top bar names whose eyes you are borrowing, so the mode is never mistaken for broken fog.

- **Ping.** `Alt` + click marks a spot on the map with an expanding ring, and it goes out to the
  players' panels too — the fastest way to say "look here" without describing coordinates.
- **Multi-select and group move.** Drag on empty ground to frame tokens, `Shift` to add to the
  selection, `Ctrl+A` for everything you control. Dragging one moves the whole group as a unit and
  each token still lands on its own square. The panel switches to bulk actions (show/hide, fog,
  delete).
- **Keyboard shortcuts:** `Delete` removes the selection (undoable), `Ctrl`+drag duplicates,
  `Q`/`E` rotate, `T` marks a target, `Esc` clears. Double-clicking empty ground opens a quick
  add-token search that drops the creature exactly where you clicked — with a count, so five
  goblins land in a spiral rather than a stack.
- **Light as a separate concept from vision.** Tokens can emit bright and dim light, and creatures
  can have darkvision. A dropped torch sees nothing but lights the room for everyone. Once a map
  has any light source the 5e rule applies: unlit ground is only seen by darkvision, and what
  darkvision alone reveals is tinted grey. Maps with no lights behave exactly as before.
- **Token facing and locking.** A facing arrow sits outside the token ring, cone templates inherit
  it, and locked tokens (scenery, chests, torches) cannot be dragged by accident.
- **Initiative order on the map**, as a strip of portraits across the top: the active combatant is
  larger and ringed, the round counter sits at the end, and tapping a portrait selects that token
  and centres the camera on it. The turn can be started and advanced from there.
- **Drag-to-reorder initiative** in the encounter list, for ties you settle by hand rather than by
  dice.
- **Quick damage and healing** from a token's context menu, plus camera lock, duplicate and target
  from the same place.
- **Area templates have presets** (15/30 ft cone, 10/20 ft radius, 30/60 ft line, 10 ft square).
  With a token selected the template starts at that token and inherits its facing.
- **Scene audio.** A battle map can carry a playlist and an ambience track; showing the map to
  players starts both. Ambience is a second, always-looping audio layer with its own volume, so
  rain or a cave echo plays *under* the music instead of replacing it.
- **Copy a map elsewhere** — grid, walls and object tokens travel; creatures, fog and the encounter
  link stay behind, so a prepared tavern can be re-used without last session's fight.
- **Quick session note** from the map's top bar, and **advance time** from the journey sheet.
- **Collapsible world graph nodes.** A place can fold its whole subtree away; the node shows a
  "+N" badge and the hidden places' links are re-routed to it so the graph does not come apart.
- **Grid calibration mode.** Instead of guessing cell size and offset with numeric steppers, the
  new tool lets you frame the squares you can see on the map (1x1 up to 5x5). The frame stays
  editable — drag a corner to resize, the middle to move — and you can zoom and pan while it is up.
  Applying it is undoable.
- **Encounters and battle maps are wired together.** The encounter screen opens its battle map in
  one tap, asking which place it happens in the first time, and drops every combatant onto the map
  as a token — players down the left edge, monsters down the right. Combatants that already have a
  token are skipped, so re-running it fills gaps without disturbing your layout. The map panel has
  the same action.
- **Any place can become a battle map** without first uploading a region map or creating a child
  place. The battle map button is always available, and a map with no image offers to pick one.
- **Interface density setting** (Compact / Normal / Comfortable) in Settings, defaulting to
  Compact. Padding, control heights, spacing and text size all derive from it, so the whole app
  tightens or loosens together.

- **Battle maps.** Any location with a map image now opens a full tactical map: a configurable
  grid, drawable obstacles, tokens, and explorable fog of war. It is a separate screen from the
  pin/route map, and the DM shares it with the table explicitly — preparing a map no longer drops
  it onto the players' screens.
  - **Obstacles** are line segments with ten types, each answering three independent questions
    (does it block sight, movement, sound): wall, perimeter wall, door, secret door, illusory door,
    window, portcullis, foliage/curtain, railing, and sound barrier. The perimeter wall blocks
    sight from **one side only** and the blocked side is flippable, so a round tower can be drawn
    without the interior going dark. The illusory door blocks sight and sound but is walked
    through. Draw with click-drag or chain-click, snap to the grid, right-click or Esc to finish.
  - **Doors** are interactive for players; **secret doors** are the DM's alone — until revealed
    they are sent to the client *as plain walls*, so the packet itself carries no hint. Locked
    doors refuse players and open for the DM.
  - **Fog of war** is two-layered: never-seen (black) and seen-but-not-currently-visible (dim).
    Tokens reveal what they can actually see — vision is a ray-cast polygon against the obstacles,
    so a corner casts a real shadow and an opened door lights the corridor behind it. Exploration
    is remembered per cell as a packed bitmap (a 60x40 map is 300 bytes) and survives grid resizes.
    The DM can paint fog by hand in either direction and reveal or cover the whole map.
  - **Grid scale** is configurable: cell size in image pixels, X/Y offset, how much each cell is
    worth, and the unit — feet, miles, meters or kilometers. Switching units converts the number
    rather than reinterpreting it (5 ft becomes 0.000947 mi, not 5 mi). Distance counting follows
    5e by default (diagonals free) with 5-10-5 and Euclidean as alternatives.
  - **Movement modes** apply to players only — free, locked, or only on their turn in initiative.
    The DM is never restricted. Every rule is re-checked on the server: a crafted packet cannot
    walk through a wall, move someone else's token, or act out of turn.
  - **The movement ruler** draws while you drag a token or step it with WASD/arrow keys. It follows
    the actual route from the square the turn started on, and each stretch keeps the colour it was
    drawn in: green within speed, yellow between speed and dash, red beyond. A stretch that crosses
    a threshold is split exactly at the crossing. The ruler resets at the start of each round.
  - Players get their own battle map tab: they drag their own token, open doors, and see the fog
    lift as they go. Obstacles in unexplored areas and tokens behind walls are never sent.
  - **Levels.** A battle map holds any number of levels, each with its **own image, grid alignment,
    obstacles, tokens and fog** — a dungeon floor is its own drawing. The DM switches levels from
    the side panel and players follow; tokens can be moved between levels.
  - **Hex grids**, pointy-top or flat-top, alongside square. `cellSize` keeps its meaning in every
    shape (distance across flats), so switching does not throw the alignment away. Distance in hex
    is cube distance — there are no diagonals, so the 5e/5-10-5/Euclidean choice is hidden.
  - **Area templates** — sphere, cone, line and cube. Drag from the origin for direction and
    length; it stays transient until you **pin** it, at which point it is saved with a
    "visible to players" switch. The squares actually covered are highlighted, which is the
    question the table is really asking. **Players get the tool too** and can pin their own
    (each player can only remove their own; the DM can remove any).
  - **A measuring ruler** that does not move anything: drag, or click point by point.
  - **Tokens carry their combat row**: a health bar (green→red), an AC badge, condition labels and
    an elevation badge. Players see exact HP and AC only for player characters — monsters send the
    same coarse health label the initiative list already used.
  - **A sound tool.** Pick a token and a hearing polygon is swept against the *sound*-blocking
    obstacles (the same sweep as vision, different criterion); every token the area touches is
    ringed and counted. Closed doors and walls stop it, railings and foliage do not.
  - **Per-player fog.** Fog can be shared by the party (the default) or private to each character;
    in private mode the DM sees the combined discovery and can preview any single player's fog from
    a selector, while each player only ever receives their own.
  - **Editing conveniences**: drag a selected obstacle's endpoints or its body to fix it, align the
    grid by dragging a handle on the map (body moves the offset, the corner resizes the cell), and
    undo drawing steps. Undo covers obstacle and template edits — not token moves, which are plays
    rather than mistakes.
  - Tokens added from combat now take their **size from the creature** (Large is 2x2, Gargantuan
    4x4) and their **portrait** from the character or monster record, and portraits now reach
    players. The movement ruler shows while you drag or step with WASD, fades out after you stop,
    returns with the accumulated colours when you move again, and clears when the round advances.

- The character sheet's inventory is split into an **Equipped** tab and a **Bag** tab. Equipped
  items are grouped into body slots (head, armor, cloak, gloves, boots, belt, main hand, off hand,
  amulet, ring), and each slot enforces a capacity: one helmet, one suit of armor, one shield, and
  so on.
  - Every cap is editable per character from the chip next to the slot, including "unlimited", so
    a table that plays with two rings per hand or a second amulet is not fighting the app. Rings,
    amulets and the catch-all "other" slot ship unlimited by default because nobody counts trinkets
    at the table.
  - An item's slot is inferred from the library record (armor data, weapon data, category) and from
